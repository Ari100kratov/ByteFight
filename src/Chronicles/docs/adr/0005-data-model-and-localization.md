# ADR 0005: Модель данных хроник и локализация бизнес-данных

## Статус

Принято

## Контекст

Подсистема хранит:

- справочник номинаций;
- агрегированную статистику персонажей;
- исторические записи достижений;
- локальный inbox интеграционных сообщений.

Дополнительно требуется, чтобы видимые пользователю бизнес-данные на старте были русскоязычными.

## Решение

### Основные таблицы

- `ChronicleNominations`
- `CharacterNominationScores`
- `ChronicleRecords`
- `CharacterChronicleStats`
- `InboxMessages`

### Принципы хранения

- `ChronicleRecords` являются append-only историей;
- `CharacterNominationScores` являются текущей read-model для лидербордов по номинациям;
- `CharacterChronicleStats` являются агрегированной read-моделью;
- `InboxMessages` являются локальным буфером и журналом обработки внешних событий;
- пользовательские названия и описания базовых номинаций seed'ятся на русском языке через миграции;
- metadata номинации (`MetricLabel`, `MetricUnit`, `ValueKind`, `SortDirection`) хранится в таблице `ChronicleNominations`, а визуальные иконки и цветовые акценты остаются ответственностью UI.
- доменная сущность `ChronicleNomination` не содержит in-memory default catalog, чтобы не было второго источника истины рядом с миграциями.
- строки номинаций хранят snapshot отображаемых данных участника: имя/фамилию пользователя, имя персонажа, класс и специализацию.

### Локализация

На текущем этапе русские названия и описания хранятся непосредственно в данных номинаций.
Это допустимо, пока:

- продукт ориентирован на один основной язык;
- нет полноценного слоя мультиязычных справочников.

Если появится многоязычность, справочник номинаций должен эволюционировать в одну из моделей:

- таблица переводов;
- resource-driven локализация по `Code`;
- внешний dictionary service.

## Последствия

### Плюсы

- данные готовы к прямому использованию в UI без дополнительных словарей;
- схема остаётся простой;
- различаются исторические записи, агрегаты и integration buffer.

### Минусы

- прямое хранение русского текста в seed-данных не является финальной моделью для мультиязычности;
- при интернационализации понадобится отдельный этап миграции.
