# ADR 0003: Контроль качества фронтенда и разбиение бандла

## Статус

Принято

## Контекст

React-клиент уже использовал строгие настройки TypeScript, но в нем не было общего
контракта по стилю, линтингу и форматированию. Production-сборка Vite также показывала
предупреждение о слишком большом чанке: страницы фич, Pixi-рендеринг и код редактора
попадали в начальный граф приложения.

На бэкенде уже включены анализаторы, warnings-as-errors и централизованные настройки
сборки. Основной найденный пробел был в том, что `IDE0005` был отключен, поэтому лишние
`using` не контролировались сборкой.

## Решение

- Для фронтенда добавлен quality gate на ESLint flat config, `@typescript-eslint`
  recommended-правила, правила React hooks и Prettier.
- Prettier использует Tailwind-плагин, чтобы порядок utility-классов был стабильным.
- ESLint закреплен на стабильной 9.x major-версии: ESLint 10 в текущем графе зависимостей
  проявил проблемы с package resolution.
- Клиент переведен с `@vitejs/plugin-react-swc` на `@vitejs/plugin-react`, чтобы убрать
  предупреждение Vite 8 о deprecated `esbuild` option из SWC-плагина.
- Route-level страницы грузятся через `React.lazy` и `Suspense`.
- Monaco setup загружается только внутри фичи редактора кода, а не из `src/main.tsx`.
- В Vite оставлены явные vendor-группы для React/router/query и UI-библиотек. Pixi не
  принудительно собирается в один vendor chunk: Rolldown разбивает его внутренние модули
  на более мелкие route-loaded чанки.
- На бэкенде `IDE0005` включен как warning. Так как warnings трактуются как errors, лишние
  `using` теперь ломают сборку.

## Команды

Из `src/ClientApp`:

```powershell
pnpm.cmd lint
pnpm.cmd format
pnpm.cmd build
```

Из корня репозитория:

```powershell
dotnet build ByteFight.sln --no-restore
```

## Последствия

- Начальный frontend-бандл стал существенно меньше, а игровой код и код редактора
  загружаются ближе к маршрутам, которым они нужны.
- Текущая production-сборка Vite больше не показывает предупреждение о чанках больше
  500 kB.
- Форматирование приведено к одному стабильному стилю вместо накопления локальных
  расхождений.
- Type-aware unsafe-правила, строгие TypeScript-правила и правила React hooks включены в основной
  `pnpm.cmd lint`, который запускается с `--max-warnings 0` и является единым обязательным порогом
  качества фронтенда.
